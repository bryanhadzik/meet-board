How it works

Your observation is the one that makes this buildable: once the session starts, the entry data doesn't change. That splits the board into two sources with very different demands.

SourceWhat it carriesChanges
meet.json — the flat fileEvery event, every heat, every lane: swimmer, team, seed time. Plus the team table and colors.Written once at session start. Re-export only on a deck change.
The CTS consoleCurrent event, current heat, running time, lane times, places.Continuously, over the scoreboard serial link.

The board joins them on event + heat. Everything on the right-hand panel — the whole reason parents look up — comes from the flat file alone and needs no live feed at all. Which means the up-next panel works even if the console link drops.

This sidesteps the Meet Maestro problem

Tooele's swim program runs on SwimTopia, and Meet Maestro's only scoreboard integration is a one-way start-list export — which is why the earlier "live up-next" designs were dead ends. But a one-way export at session start is exactly what this architecture wants. The limitation stops mattering. Re-export whenever you make deck changes, heat and lane edits included.

The flat file

{
  "meet": "Tooele County Tri-Meet",
  "venue": "Tooele High School Natatorium",
  "date": "2026-12-11",
  "laneCount": 6,
  "homeTeam": "TOOEL",

  "teams": {
    "TOOEL": { "name":"Tooele", "mascot":"Buffaloes",
               "color":"#D18AE0", "alt":"#E8EEEE", "colorName":"purple" },
    "STAN":  { "name":"Stansbury", "mascot":"Stallions",
               "color":"#3D8BF5", "alt":"#9AA6AB", "colorName":"royal blue" }
  },

  "events": [
    { "no":14, "name":"Girls 100 Freestyle", "distance":100,
      "heats": [
        { "no":1, "lanes":[
            { "lane":1, "name":"S. Strand", "team":"STAN", "seed":"1:04.58" }
        ]}
      ]}
  ],

  "scores": [ { "team":"TOOEL", "points":84 } ]
}

Producing it takes one step in Meet Manager and a short converter:

  1. Meet Manager → File > Export > Start Lists for Scoreboard > Start Lists for CTS. You get one .scb per event, each carrying the event name and number, the heat count, and per-lane athlete and team abbreviation. Meet Maestro exports the same family of files.
  2. A converter walks that folder and emits meet.json. It's a small script — the .scb format is fixed-width text and well documented, and OpenSwimScoreboard already contains a working parser you can lift.
  3. Drop meet.json next to this page. The board picks it up automatically; with no file present it falls back to the sample data you're looking at.

Team colors

Tooele High is 4A Region 11 under the UHSAA 2025–27 alignment, and for this cycle swimming uses the same region map as everything else. That's a change from 2023–25, when Tooele swam in a Salt Lake–based Region 10 — Wikipedia and the 2025 UHSAA region swim guide both still show the old grouping.

Region 11 is geographically split: three Tooele County schools and five in Cache Valley, about a hundred miles away. In practice you'll render Tooele, Stansbury, Grantsville and Deseret Peak most weeks, Salt Lake Valley opponents next, and the Cache Valley schools only at invitationals and the region championship.

That almost certainly has authoritative values for Tooele, Stansbury, Grantsville and Deseret Peak — four of the five schools you'll actually render. Five minutes with it in a browser and you can replace the top four rows. The abbreviations come from the 2026 4A state psych sheet, which is the right source since they're Hy-Tek team codes — but confirm them against the raw PDF, and note Deseret Peak has no code yet (brand-new program).

Why the colors aren't simply the school colors

Two constraints turn "use the team colors" into a real design problem.

Half these schools wear black or navy. On a dark board those disappear. Each school's board color is therefore a display tint — the school's hue, lifted until it clears 3:1 contrast against the board background. Bear River, whose colors are black and white, correctly gets white.

And four of the nine wear blue. Checked with a contrast validator, Tooele's purple against Stansbury's royal blue lands at ΔE 17.7 for normal vision — fine — but only 6.6 under protanopia. Purple against blue is genuinely hard for red-blind viewers; that's optics, not a fixable palette. So the board never uses color alone: the team abbreviation sits beside every stripe, in the team color, on every row of both panels. Color is how you find your school in half a second; the abbreviation is what makes it certain.

Where two teams in the same meet really are too close, the board resolves it at load time rather than at design time:

Home team keeps its primary color.
For each other team, in order:
  if ΔE(primary, every color already assigned) < 15
     and the alternate clears 15 → use the alternate
  otherwise → keep the primary

ΔE is computed in OKLab in the page itself, so the rule runs on whatever teams actually show up — including opponents from outside the region that you add to the file later. Give every school an alt drawn from its real secondary color and the rule has something to work with.

Putting it on the wall

  • Serve it over HTTP from the timing-table PC, not from the filesystem — browsers block a local page from reading a local JSON file. Any tiny static server will do.
  • One PoE signage player per TV, in kiosk mode, pointed at that URL. They stay powered and stay on the page; a switch-port bounce reboots one from the equipment closet.
  • Delete the preview controls. The buttons under the board exist for this page only.
  • The layout is eight rows and holds at 65″ from about 39 ft. Two panels side by side rather than stacked is what keeps it inside that budget — twelve swimmers on screen, still only six rows tall. Measure the farthest seat from the nearer screen before you buy panels.
  • Serve a fallback page — facility logo, session schedule, pool records — so the screens never read "No Signal" between sessions.
